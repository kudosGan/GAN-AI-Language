## The three stages

In the world of GAN, a small language being built in Go, the journey of turning a simple text file into a running program is divided into three main stages: the lexer, the parser, and the interpreter. Each stage has its own dedicated file: `lexer.go` for the lexer, `parser.go` for the parser, and `interpreter.go` for the interpreter. 

First, the lexer (found in `lexer.go`) takes the raw text of your GAN program and breaks it down into smaller pieces called tokens. Tokens are like the building blocks of your program, and they include things like `IDENT` (which stands for an identifier, like a variable name), `NUMBER` (for numbers), `STRING` (for text), and `PLUS` (for the plus sign, +). If the lexer encounters something it doesn't recognize, it marks it as `ILLEGAL`.

Next, the parser (in `parser.go`) takes these tokens and organizes them into statements and expressions. Think of it as putting the building blocks together to form a structure. For example, it might turn `IDENT` and `NUMBER` tokens into an assignment statement like `x = 5`.

Finally, the interpreter (in `interpreter.go`) takes the organized statements and expressions and runs them, making your program do what it's supposed to do. The `main.go` file acts as the conductor, reading your `.gan` file and connecting it to the lexer, parser, and interpreter so that your program can run smoothly.

## Statements and expressions (read from parser.go)

A **statement** is something the program does. An **expression** is something that has a value.

**Statements**

- `PrintStatement`
- `LetStatement`
- `IndexAssignStatement`: Target[Index] = Value. Changes one item of a list.
- `ImportStatement`: import "path". Loads a library or another .gan file.
- `ForStatement`: for Var in From to To { Body } counts from From up to To (both included). If there is no "to", Iter is a list to go through instead.
- `IfStatement`: if Condition { Then } else { Else }. Else is empty if there is no else.
- `WhileStatement`: while Condition { Body }. The body repeats while the condition is true.
- `AssignStatement`: name = value. Changes a variable that already exists.
- `FuncStatement`: func Name(Params) { Body }. Defines a function.
- `ReturnStatement`: return Value. Ends the function and hands back Value.
- `ExprStatement`: is a call written on its own line, e.g. greet("GAN"). Its value is thrown away.

**Expressions**

- `StringLit`: "hello"
- `NumberLit`: 5
- `VarRef`: x
- `BoolLit`: true or false
- `ListLit`: is a list written out: [1, 2, 3]
- `IndexExpr`: picks one item out of a list (or one character out of text): Target[Index]
- `LogicExpr`: is "and" / "or": Left Op Right. It stops early when the answer is already known.
- `CallExpr`: is a function call: Name(Args), e.g. add(2, 3). It has a value if the function returns one.
- `MemberExpr`: reads a variable that lives inside a module: math.PI
- `UnaryExpr`: is an operation on one value: -Operand, e.g. -5 or -x
- `BinaryExpr`: is an operation on two sides: Left Op Right, e.g. 2 * 3 or x > 5
- `Param`: is one parameter of a function, with an optional type.

## How precedence works

In the GAN language, the parser works through expressions by breaking them down into smaller parts based on the precedence of operators. This means that when the parser encounters an expression like `2 + 3 * 4`, it first looks at the multiplication (`*`) because it has a higher precedence than addition (`+`). The parser calls the `parseTerm` function to handle the multiplication, which in turn calls the `parseSum` function to handle the addition. This process ensures that the expression is evaluated correctly, resulting in `2 + (3 * 4)`, which equals `14`.

The parser accomplishes this by having a series of functions, each responsible for a specific level of precedence. For example, the `parseTerm` function handles multiplication and division, while the `parseSum` function deals with addition and subtraction. Each function calls the next lower precedence function to handle its parts, ensuring that the correct order of operations is followed.

Parser functions (read from parser.go):

- `parseExpr`: reads a whole expression: conditions joined by "or".
- `parseAnd`: reads conditions joined by "and".
- `parseNot`: reads "not" followed by a condition, or just a comparison.
- `parseComparison`: reads a comparison, or just a plain value if there is no comparison.
- `parseSum`: reads terms joined by + or -.
- `parseTerm`: reads values joined by * or /.
- `parseUnary`: reads a value that may have a minus sign in front: 5, -5, or even --5.
- `parsePostfix`: reads a value, then any [index] written after it: names[0], grid[1][2], f(x)[0].
- `parsePrimary`: reads one value: a string, a number, a variable name, a function call, or a whole expression inside ( ).
- `parseCall`: reads the ( arguments ) part of a call. The function name is already consumed.
- `parseOptionalType`: reads ": number" if there is a colon next. It returns "" if there is none.
- `parseBlock`: reads statements until the closing }. The opening { is already consumed.
- `parseStatement`: reads one command: print, let, if, while, func, return, an assignment or a call.
